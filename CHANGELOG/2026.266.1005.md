## Summary of changes

Relocate the `check-doctor-local` R10 witness (and its `check-doctor-app` `kind:local` template) out of `opencharly/charly`'s root `charly.yml` into `candy/plugin-doctor`'s OWNING repo, so the witness that proves the externalized `charly doctor` command lives beside the plugin it exercises. The check-bed runner's dev-tree override (`proc.SelfSuperprojectOverridePair`, `spec/proc/repo_override.go`) points a bed PROJECT's own superproject `@github` refs at the local tree; in this umbrella every submodule's superproject is `opencharly/opencharly` (which hosts no candies), so a plugin candy owned by another repo was never exercised as in-development code while its witness sat in `charly`. Relocated here, the template composes the LOCAL `plugin-doctor` candy with no `@github` pin.

- `charly.yml` — the root manifest (already a project via `discover:`) now also declares the moved `check-doctor-app` (`kind:local` template composing the LOCAL `plugin-doctor` candy) and `check-doctor-local` (`disposable: true`, `host: local`, `lifecycle: dev`, plan step `doctor-runs` asserting `${CHARLY_BIN} doctor` exits 0 and stdout contains `Container Engine`); the `version:` schema stamp advances `2026.232.0520` → `2026.249.2125` (the schema head the moved bed entities — and therefore the CI gate — require); the now-false "This file declares no entities of its own" header comment is swept.
- `.gitignore` — NEW file (this repo previously had none): the standard generated-artifact rules (`.build/`, `.containerignore`/`.dockerignore`, `.check/`, `output/`, editor scratch `*.swp`/`*~`, and `*.bak`/`*.bak.*` migration rollback backups). It belongs because adopting the root `charly.yml` as a real project means `charly` now writes generated state into the repo root — this very R10 run created `.check/check-doctor-local/2026.266.0954/`, which must not be committed.
- `.github/workflows/deploy.yml` — the CI gate builds `charly` from a PINNED source tag and runs `charly box validate` at the repo root. The pin advances `v2026.238.1242` → `v2026.256.1316` because the root `version:` stamp moved to the `2026.249.2125` schema head and the file now declares the `check-doctor-*` entities, so the CI charly must be a release at/after that head (the old pin predates it). The gate content is unchanged — only the pinned charly release it builds and validates with moves.
