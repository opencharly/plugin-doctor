**Two things this body deliberately does NOT claim, because they are worth stating.**

- **A duplicate exists for now, and the generator tolerates it.** The carrier still
  declares the same `(kind, family, name)`; `plugin-marketplace`'s `preferEntity`
  (`resolve.go`) dedupes on exactly that triple, so one page is published — currently the
  carrier's, until its node is removed. This PR does not prove the dedupe path; the
  carrier-removal PR (opencharly/opencharly#600) and the `marketplace` refs switchover do.
- **The node KEY is not the identity.** A `skill:` node's id is its `name:` when it
  states one (`spec#247`), which is why `<name>-skill:` keys and the `name:` field can
  differ without consequence.

**Producer-first.** No carrier loses a node here: those removals and retirements belong
to the session that claimed the carriers (opencharly/opencharly#600).
