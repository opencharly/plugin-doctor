# 2026.286.1728 — test(doctor): the bed asserts the report's content, not only its liveness (#13)

## Summary

`check-doctor-local` — this repo's own disposable bed, and therefore the R10 gate for any change to `candy/plugin-doctor` — asked only whether `charly doctor` **runs**: one step, `exit_status: 0`, `stdout: [contains: 'Container Engine']`. So a change to any single capability line passed it, and a report that silently dropped a whole capability group passed it too. That is this issue, found while gating a real change to this plugin.

The fix asserts the report's **content**, not its liveness — three more lines every host on this bed's class must produce:

```yaml
              stdout:
                - contains: 'Container Engine'
                - contains: 'libvirt session socket'
                - contains: 'qemu-system-x86_64'
                - contains: 'gocryptfs'
```

The libvirt session socket is deliberately first among them: it is the line whose *resolution* the plugin's `distroFamily` change (this repo's `#14`, merged) touched, so the bed now fails if a doctor silently stops reporting it.

## How tested

**The bed itself, on a dev-built binary carrying this branch** — the only route that means anything for a compiled-in plugin (running the bed as-is reports on the published plugin):

```
bootstrap-charly.sh --dev-plugin plugin-doctor=<this worktree>     →  rc=0
charly -C <this worktree> check run check-doctor-local
  [bring-up-members] PASS · [check-live] PASS 13.307s · [update] PASS 2.652s
  [cleanup] PASS 19.293s · [cleanup-members] PASS
  check-doctor-local: PASS (steps=6)          run 2026.286.1720
```

**And the assertions are real assertions, checked against a host this bed runs on:** the three added lines are present in the report here, which is why the strengthened bed passes rather than failing on its own new expectations. A bed that only asserted liveness could not have told the difference.

- **R9** — the binary was rebuilt for the gate via `bootstrap-charly.sh --dev-plugin`, not a shared install.
- **R10** — `check-doctor-local`, `disposable: true`, on this committed tree, zero warnings.
- **R0** — this repo's own list loaded before acting: `/charly-core:charly-doctor` and `/charly-internals:plugin`; `/charly-internals:git-workflow` before the git/gh actions.

**Scope, stated rather than implied:** this strengthens *what the bed checks*. It does not make the doctor's own checks correct — a capability line still present but answering the wrong question remains undetectable by this bed, and that is a separate question about the plugin's own probes.
