# 2026.286.1554 — fix(doctor): resolve the libvirt hint through the distro family, so Arch derivatives get a working hint

## Summary

`charly doctor` picked its Arch-family libvirt install hint with `distro.ID == "arch"`. On any host whose ID is a derivative — CachyOS here, and every future one — that branch falls through to `systemctl --user enable --now libvirtd.socket`, **a command that installs nothing on a host class that has no systemd user units**, while the bed machinery spawns the daemon on demand and VM beds run fine.

Two lines, both in idioms this repo already has:

- `command.go:544` — `if distro.distroFamily(distro.ID) == "arch"`, i.e. ask the resolver that `installHint` already uses, instead of comparing a raw ID;
- `data.yml` — `cachyos: arch` in `distro_family_map`, which already maps `ubuntu/pop/linuxmint -> debian` and `rhel/centos -> fedora` and had **no Arch derivative at all**, which is why the fall-through happened.
